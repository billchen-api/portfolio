The Challenge
Rebuild it on the new platform, topology first.

Nexus Dashboard Data Broker is a highly technical product for routing network data. Its logic runs deep, and the old interface exposed most of it through dense configuration forms and a static topology map.

As lead product designer, my job was to turn that routing logic into workflows operators could follow, and to rebuild the app on the unified Nexus Dashboard platform. I worked closely with product management and engineering to give each data stream a clear mental model, and used the platform’s design system so our time went into the hard part: deep backend constraints on one side, everyday speed for the people running it on the other.

A loose ask

The starting requirement was simply to improve the user interface. Before designing anything, we had to agree on what the product actually did.

Operators we couldn’t reach

Deployment security kept us away from enterprise operators, so Tech Marketing stood in as our check on domain logic.

A full restructure in 2.5 months

The app had to move onto the unified Nexus Dashboard framework on an aggressive timeline.

Discovery
Map the old tool before changing it.

With only a loose brief to work from, I sat down with engineering, technical marketing and product leadership and mapped what the existing system actually did. The goal was simple: no critical workflow gets lost in the redesign.

That map let us modernize the visual language while keeping full feature parity, and it pointed us to the biggest opportunity, the topology map, which became much faster to work with.

Ideation
One framework, then the wireframes.

With no direct access to users, I worked through the core operational use cases and system constraints across the Nexus Dashboard suite. I turned them into one product framework that covers every page and object in the app.

From there I built structural wireframes and ran rounds of prototyping and feedback with engineering. Each round simplified the layout hierarchy, so administrators could move through dense data without getting stuck.

Observability

A Home for System Health

There was no single place to check whether the system was healthy, so I designed one. The dashboard shows live traffic statistics, node status and component utilization at a glance.

Each panel turns a passive number into something an operator can act on, which cuts the time spent hunting for the cause of a problem.

Topology

A Map You Can Work In

The old topology map was a static visualization. I turned it into an interactive canvas: administrators select a node, see its live status and configure it right there, without jumping to separate configuration pages.

Setup

Setup Flows You Can See

Setup used to mean filling in text boxes and dropdowns, one after another. I replaced them with visual components for the complex choices, like picking edge ports and building a connection from source to filter to monitoring tool.

People can read the setup at a glance, so they move through it faster and make fewer mistakes.

Built on the Platform
Every page speaks Nexus Dashboard.

I restructured the application pages to fit fully into the Nexus Dashboard platform and used its design system components throughout.

The interface now looks and behaves the same way everywhere, each page is easier to use, and the team has a reusable base for future platform updates.

Reflection

Governance, Speed and Scale

Shipping on an aggressive release cycle took clear communication and quick alignment in a complex technical domain. Beyond the screens themselves, I put real effort into working well with engineering, so we got the most out of our shared component library.

Working with distributed global teams, I set interface patterns that fixed pressing usability problems and gave the team a practical framework for future product updates.
