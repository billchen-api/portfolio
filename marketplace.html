The Challenge
Many vendors. One catalog.

As lead designer for the platform, my job was to bring a scattered set of third-party cloud services into one self-service marketplace.

The hard part was hiding complexity. Vendors priced and licensed their software in different ways, and private-cloud deployment came with highly technical settings. Enterprise IT buyers needed all of it in one consistent catalog they could use on their own.

Key Screens
Browse, configure, check out.

Catalog grid

One Grid for the Whole Catalog

One dashboard holds the entire launch catalog. Third-party cloud services sit in a scannable grid, grouped by provider type and infrastructure function: application services, data analytics and developer tools.

IT operators can scan what’s available, switch between vendor categories and see pricing at a glance, without digging through pages.

Inline configuration

Configure Without Leaving the Catalog

Selecting an application opens a panel inline with its full details, so buyers keep their place in the catalog. This panel is the configuration template that fits every vendor’s model.

Pricing tiers, deployment options and hardware specs sit in the same panel, so buyers set options and check infrastructure compatibility in one place.

Checkout

See the Cost Before You Order

A split-panel checkout walks buyers through the last deployment settings and financial sign-off. As they pick a hosting environment, region and storage scale, the order summary updates the cost in real time.

It replaces manual ordering paperwork, and procurement teams see the full cost and configuration before they commit to a deployment.

The Solution
One Storefront, From Discovery to Checkout

I defined one storefront framework that brings service discovery, configuration and purchase together in a single-page workflow.

A configuration interface that updates in real time made complex deployment settings simple. It took the paperwork out of buying enterprise cloud software and gave every vendor’s application the same clear path to purchase.

Design System
One Spec Across the Cloud Portfolio

To keep the wider cloud portfolio consistent, I set up a central design spec as the single source of truth for our UI patterns: core components, interaction behaviors and a custom icon library for infrastructure metrics.

With the guidelines written down, product teams could build marketplace features on their own and still look consistent, with less duplicate front-end design work.

Reflection

Building the Keynote Demo

The marketplace launched, then was shut down soon after for reasons outside UX and design.

For the CiscoLive! keynote, I helped build the demo and helped write its script, then taught the executives what to say and where to click. Working directly with SVPs and Directors also got product engineering, product management and leadership onto one long-term roadmap.
